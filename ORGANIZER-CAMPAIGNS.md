# Кампании организатора

В навигации появились две рабочие области: **Мой арсенал** и **Кампании**.
Организатор создаёт кампанию без арсенала. Если он играет, то подключает свой
арсенал кнопкой «Подключить мой арсенал» и становится обычным участником.
Владение кампанией и участие в ней независимы.

## Сценарии

- Создать кампанию, указать длительность, менять текущую неделю и договорённости.
- Скопировать приглашение. Игрок входит в аккаунт и явно подключает свой
  арсенал. Организатор получает доступ к просмотру последующих облачных версий.
- Добавить старое публичное досье по ссылке или ID. Ссылка на приватный арсенал
  не даёт доступа: его владелец должен присоединиться по приглашению.
- Просматривать досье, лидера, модели, травмы, снаряжение, продвижения и личную
  историю; переключать участников, сохраняя раздел. Снимки карточек моделей
  доступны в раскрывающемся блоке.
- Вести общую хронику и видеть число игр/побед участников из их досье.
- Выйти из кампании, удалить участника, заменить приглашение или удалить
  кампанию. Удаление связей никогда не удаляет арсеналы.
- Перенести старую кампанию через ссылку и её ключ организатора. Копируются
  параметры недели, участники, статистика и общая хроника. Арсеналы к перенесённым
  участникам привязываются отдельно. Исходные данные и старые ссылки сохраняются;
  повторный перенос той же кампании тем же владельцем открывает уже созданную.

Просмотр использует отдельный DOM, построенный чистой функцией того же
рендерера, что и печать. Он не вызывает `replaceState`, не пишет в localStorage
и не участвует в автоматической синхронизации личного арсенала.
Параметры `group` и `participant` восстанавливают выбранную кампанию и участника
после перезагрузки. Поздние ответы предыдущего участника отбрасываются.

## Данные и права

Миграция `worker/migrations/0005_organizer_campaigns.sql` добавляет три таблицы:

- `organizer_campaigns`: владелец, название, неделя, длительность,
  договорённости, приглашение, версия настроек;
- `organizer_members`: связь кампании и существующего арсенала из `campaigns`;
- `organizer_events`: самостоятельная общая хроника.

Существующая таблица `campaigns`, приватность аккаунтов и старые API не меняются.
У аккаунта по-прежнему один автоматически синхронизируемый личный арсенал.
Созданных организатором кампаний может быть несколько. Один арсенал технически
может участвовать в нескольких группах: они видят одну и ту же облачную версию.

API `/api/organizer-campaigns` использует существующие аккаунтные сессии
`X-Account-Session`, проверку Origin и ограничение частоты запросов Worker.
Список кампаний доступен только их организатору и участникам. Полное приватное
досье доступно через конкретную связь только организатору и владельцу арсенала;
остальные участники видят имя, команду, фракцию и число игр/побед, но не досье.
Приглашение доступно только организатору. Участник может удалить собственное
участие. Организатор не получает права изменять чужой арсенал.

Настройки защищены номером версии: устаревшая запись получает HTTP 409.
Уникальность привязок и каскады обеспечиваются базой. Удаление арсенала очищает
ссылку участника, а не удаляет общую кампанию.

## Границы первой версии

- Общая неделя не переписывает личные недели и незавершённые игры игроков.
- Нет редактирования чужих арсеналов, автоматического объединения результатов
  двух игроков в одну общую игру и фоновых уведомлений.
- Для кампаний нужна сеть. Личный арсенал сохраняет существующий локальный режим.
- Обновление просмотра получает последнюю сохранённую облачную версию, а не
  несохранённый ввод на устройстве игрока.
- Автоматическая классификация старых записей не выполняется: перенос запускает
  владелец ключа организатора.

## Проверки и выпуск

Из корня проекта: `npm run check`, `npm run test:organizer`,
`npm run test:kan25`, `npm run test:kan122`, `npm run test:kan174`.
Из `worker`: `npm test`. Браузерные проверки используют установленный Edge;
при необходимости задайте `BROWSER_CHANNEL=msedge`.

Новый браузерный сценарий работает с настоящими обработчиками Worker и SQLite
в памяти, не обращаясь к рабочей базе. Проверяет собственное участие,
приватные приглашения, выход, смену участников при запаздывающем ответе,
сохранность локального состояния и отсутствие лишних облачных записей,
настройки, хронику, перезагрузку, мобильную ширину и английский интерфейс.
Снимки интерфейса: `.artifacts/organizer/desktop.png` и `mobile.png`.

Порядок публикации: резервная копия D1 → применение миграции 0005 → публикация
Worker → публикация статических файлов. Новая миграция только добавляет таблицы;
существующие арсеналы не переписывает. Обновлены версии ресурсов app.js,
account.js и print.js для сброса браузерного кэша.
Не публикуйте один интерфейс без соответствующего API и миграции.
